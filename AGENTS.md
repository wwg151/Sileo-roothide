# Sileo-roothide

- Work on `dev`; fetch before editing or pushing. Preserve `dev-1`.
- Build Swift/Xcode code on GitHub Actions, not on this device. Pushes to `dev` trigger `.github/workflows/build.yml` with Xcode 27.1.
- Distribution packages come from `apelin/build.sh`, declared in `apelin-project.json`: it selects the newest matching `dl/*_<architecture>.deb` by modification time and repackages it with this project's identity and `layout/version`. Roothide requires `iphoneos-arm64e` and an empty prefix; rootless requires `iphoneos-arm64` and `/var/jb`. An explicit `SILEO_INPUT_DEB` overrides selection, but must match the target architecture and app layout. The script preserves the compiled payload; it does not compile Swift or convert binaries between bootstraps.
- CI builds a matrix of `iphoneos-arm64e` (roothide) and `iphoneos-arm64` (rootless), uploaded as `sileo-roothide` and `sileo-rootless`; each run also keeps `build-log-roothide` and `build-log-rootless`. Both architectures are pushed to `wwg151/repo`'s `debs/`; only roothide is also attached to release `roothide-dev`. Download the matching artifact into `dl/` before local packaging. Both new compilation paths and device compatibility remain unverified until CI and device tests pass.
- Each CI target first runs `bash Scripts/test-functional-search.sh`, then `make clean package DEBUG=0 ALL_BOOTSTRAPS=1 SILEO_PLATFORM=<architecture> V=1`. Rootless defines `SILEO_ROOTLESS` for Swift/C and disables libroothide linkage; path adapters and CommandPath centralize bootstrap differences.
- Validate installation, upgrade, removal, package backup/repack, and configuration/source restore separately on each bootstrap. Configuration backup and restore use `/var/jb/User/Library` on rootless and `var/mobile/Library` under the current jbroot on roothide. Backup storage remains shared in Documents.
- CI publishes the roothide package and SHA256SUMS under release `roothide-dev`. Deployment to `wwg151/repo` is enabled in build.yml after the user confirmed the download/queue redesign is stable. Keep existing packages; do not add cleanup commands. Preserve remote `dev-2`, the pre-redesign backup.
- Poll the release checksum with `icli probe dl/poll_release.js` in short intervals. Download using `icli probe dl/probe_dl_deb.js`, verify SHA256SUMS, then deliver with file_show. Do not install for the user.
- Search uses package metadata plus readable native depiction text captured when viewed. Test Chinese/English concepts, natural phrases, package names/IDs, typos, ranking, detail-only matches, and recycled-cell highlighting. HTML/image-only depictions are not indexed.
- After installation by the user, verify functional search and highlight appearance on the device. CI checks do not prove UI behavior or real repository coverage.
- Put user-facing strings in Base.lproj and zh-Hans.lproj. Use 插件包 for package and 插件 for software.
- Automatic depiction translation uses Apple's private Translation framework on iOS, from iOS 15 up. The bridge asks the engine only for what the running system has: `startTranslationSession` and `textTranslationHandler` where they exist (iOS 16 answers through them), `translationHandler` before that, all looked up at run time. One translator serves the app for its lifetime. Body translation has no app-level deadline; only an explicit empty response is retried. Cancelling releases the job and ignores late callbacks. Both jailbreak targets sign the app with `Sileo/Entitlements.entitlements`; listing language pairs does not prove that translation succeeds. On iOS 16.5, verify the default-off switch and its consent prompt, an English native description and changelog, unchanged Chinese and links, the local-description fallback, and original text on service failure or when switched off. Do not use an older repackaged CI artifact to validate new Swift code.
- For package details on iOS 15+, long-press the native description or changelog to start Apple system translation directly, without text selection, confirmation, or a translation options panel, even with automatic translation off or an AI model selected. The gesture authorizes only the current page and uses its existing language choices without changing global settings. Check inline progress, failure fallback, tab and scroll position, and link taps. Use the Install/Update long-press translation options to change display modes and languages; the ellipsis has no translation item.
- Raw-format depiction prose (`useRawFormat`, HTML rather than Markdown) is translated text node by text node; tags, attributes, comments and `script`/`style`/`pre`/`code` bodies are kept byte for byte. The page can draw a partial result after processing a tab, without waiting for the full changelog or subsequent retries. Verify AI-only and system-only runs, including cache hits; the engines never mix. Untranslated fragments stay as written. Test the end of a long OpenCode changelog, a long paragraph, and prose surrounding inline code and links. A repo whose pages use raw HTML (e.g. i0s-tweak3r-betas.yourepo.com) is the case to check for this.
- The AI translation menu sits at the top right of the Updates (News) tab on iOS 15+. Verify that package details still offer per-page translation via long-pressing Install/Update, and that switching engines from News invalidates stale package-page translations. Verify provider add/edit/remove, manual model ID and searchable discovery for OpenAI-compatible, Anthropic and Gemini APIs. Test switching to and from a model, cancelling consent, changing a provider address, and removing the current provider. Confirm Keychain secrets are excluded from backup; test missing credentials, incomplete responses, network failures, and switching models while a page is translating. AI receives native depiction text fragments only. With an active model, every uncached fragment gets an AI attempt; missing or unusable translations are retried once in smaller batches and then left as written. An authorized AI model never falls back to system translation. Test slow body responses beyond the old limits and cancellation while waiting; discovery and fixed-prompt probes retain their separate short limits. Use the `DepictionTranslation` log category to distinguish timeout, HTTP failure, invalid or truncated output, and missing translations without logging prose or credentials. With automatic translation off, no page text should be sent until the user requests a translation and consents.
- A nonempty reply identical to its input is a successful no-op, not a missing translation. Cache it normally and preserve its original markup without duplicating it in comparison mode. For both engines, verify that names such as OpenCode and API identifiers don't trigger the incomplete banner, while missing or empty replies still do after retries.
- Thinking effort is saved per provider and model. Verify that unsupported models and compatible gateways never receive an effort field, model default omits it, and changing the level does not send text or restart an in-flight translation. Start another translation to verify that it uses the new level and does not reuse fragments from a different level.
